# 暑研通：搜索完善与项目检查记录

日期：2026-09-07（本地时间）

本轮通读自有后端、页面模板、测试和项目文档，追踪了在线搜索、MediaCrawler 导入、本机小红书搜索、入库、筛选、排序、分页及推荐链路。MediaCrawler 按第三方项目的集成边界审阅，没有改动其源码。现有业务数据库未被修改。

## 已完成的搜索改动

- **查询理解与召回**：保留国家、学位、学科等全部条件，兼容中英文、常见复数与连字符。搜索关键词记录 `source_query` 不再冒充原文证据；SQL 先召回各概念，再精确筛选，删除“先按质量分截掉候选”的漏召回路径。
- **筛选与排序**：过滤个人履历、过期项目和无关内容，支持中文日期、滚动截止及只有年份的截止信息。质量分异常不会使整个接口失败。语义模型不可用时自动回退；语义最多增加 5 分，仅重排前 200 个候选，后续全部合格结果仍可分页。
- **多平台去重**：按原文 URL 或明确的标题与学校组合合并重复项目；不把不同学校或未知学校的同名项目误合并。保留重复项目的多个来源，用于平台命中统计。
- **统一网页与 API**：共用在线补充、验证和排序逻辑，在排序后分页，返回完整总数。修复 API 过早截取候选、网页只显示前 200 条和部分平台计数遗漏。`/api/search` 默认在第一页补充在线结果；已有纯本地调用方可加 `live=false`。
- **真实搜索状态**：区分最新结果、近期缓存、部分失败与完全失败。合法的“没有搜索结果”不算平台故障；故障时保留其他平台及本地结果。缓存最多 128 个查询，仅缓存成功结果；中文综合搜索同时安排官方和社交来源。
- **来源与导入可靠性**：Gemini 只接收能匹配 grounding 引用的 URL；MediaCrawler 坏行隔离、dry-run 不写数据库，超时清理爬虫进程。重新抓取缺少截止日期或申请要求的摘要，不会清空已知字段。
- **页面说明**：显示内容命中词、发布日期、相关性分数及真实在线状态。论文/经验专栏说明其包含资料，不能直接视为招生公告；各平台命中数不必相加等于跨平台去重后的总项目数。

默认 Gemini 模型改为可配置的 `gemini-2.5-flash`。核查时官方列出的 `gemini-2.0-flash` 关闭日期为 2026-06-01，2.5 Flash 尚未宣布关闭日期；现有 Generate Content 搜索协议继续支持该模型。参考：[模型生命周期](https://ai.google.dev/gemini-api/docs/deprecations)、[Generate Content 搜索文档](https://ai.google.dev/gemini-api/docs/generate-content/google-search)。

## 顺带修复的已证实问题

- 首页第二页为空、登录用户只能浏览前 100 条。
- 注册页模板语法错误导致 500；修改偏好时多选框未回填已有选项。
- 详情页脚本错误处理引号和反斜杠，以及“更多来自某平台”链接用了错误参数。
- 原文预览自动跟随未经检查的重定向；现在逐跳验证公网目标并限制跳转次数。网络预览、采集及 AI 请求不再直接阻塞异步请求循环。
- 把 OpenAI 密钥交给 Gemini 接口、邮件生成网络请求没有超时、未允许搜索近期动态也调用联网工具。
- `unpaid` 被标为全奖、`early` 被判作强化学习、`campus` 被当作美国地区命中，以及推荐错误使用较旧的搜索历史。

## 验证结果与实际运行限制

**63 项自动测试全部通过**，覆盖真实 HTML/API 路由、超过 200 条的分页、来源计数、语义模型故障、采集状态、缓存、导入、模板、推荐和本机伴侣来源白名单。测试使用临时数据库与模拟外部服务；本机伴侣测试短暂监听回环地址随机端口。

复现命令：

```bash
python3 -m pip install -r requirements-dev.txt
PYTHONPYCACHEPREFIX=/tmp/summer-pycache \
DISABLE_LIVE_SEARCH=1 DISABLE_SEMANTIC_SEARCH=1 \
python3 -m unittest discover -s tests -v
```

只读检查现有索引：共 **488 条**，其中 70 条记录了 Sogou 提供商，418 条没有提供商记录；当前没有 MediaCrawler 提供商记录，且未配置启动导入路径。五个样例查询本地筛选约 0.04–0.96 秒，属于单次本机检查，不是负载基准。

一次受限真实检索“暑研 NLP”取回 **20 条候选（NSF 10、微信 10）**，未写入业务数据库。这是采集候选数，不能当作通过全部条件验证的机会数量。小红书索引返回无结果；没有执行需要真实登录态的 MediaCrawler/OpenCLI 平台对照。

**Gemini 当前密钥无效**：服务返回 HTTP 400，错误原因为 `API key not valid`。需要在本机 `.env` 更换有效的 `GEMINI_API_KEY` 并重启服务。无需把密钥发到对话里。代码已经验证该来源失败不会拖垮其他来源；模型配置更新不能修复无效密钥。

## 仍需完善的事项（按优先级）

1. **真实数据与登录态验收**：更换 Gemini 密钥，使用本人已登录的平台完成小批量采集/导入，对照平台原生结果的链接、顺序与字段完整性。现有索引对“暑研 NLP”“法国 博士”等组合确实没有合格结果，不能靠扩大模糊匹配填充。当前未新建后台监控任务。
2. **公开访问前的账号与配额保护**：密码仍用单轮 SHA-256；会话只在进程内，重置密码不会撤销旧会话。采集、分析和草稿入口没有完整权限/额度控制；还应限制登录跳转目标，并处理登录、找回密码的频率限制。需要连同旧密码迁移和部署方式一起完成。
3. **完成或隐藏账号占位入口**：Google/GitHub 登录暂无路由，“记住我”未被处理；找回密码仅输出控制台链接，却显示已发送邮件。真实邮件发送需要配置发送服务，本轮没有发送邮件。
4. **完善邮件草稿体验和数据归属**：无 API 时简历、语气、重点没有完整生效；页面使用固定学生名并可能把机会标题当论文标题。草稿保存表没有用户归属，应补齐保存/删除与前端失败恢复。
5. **数据增长后的性能与并发**：现阶段保留 SQLite LIKE 召回和最多 200 条语义重排；需要在实际规模下测量后再决定全文索引优化、同查询请求合并及全局限流。来源预览已修重定向校验；生产环境仍应通过出站网络限制进一步防御 DNS 重绑定。

Gemini 引用对应仍包含保守的标题重叠规则，只能降低无依据链接进入索引的风险，不是对招生状态或全文事实的独立验证。当前新建的测试与文档没有替代真实平台持续验收。
