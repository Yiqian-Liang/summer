# 推荐算法设计（2026-09-08）

## 目标

在“可解释 + 稳定 + 可控开销”约束下提升机会发现效率。

## 现有评分结构

### 1）查询与搜索层

- `search_ranking.py` 负责候选验证与基础分：
  - 多语概念命中（短语粒度）
  - 来源可靠度加权（大学/官方源更高）
  - 招生信号、过期与可疑 profile 过滤
  - 时间衰减分（更偏向近 30/180 天）
- 去重：URL、标题+机构双重去重。
- 语义重排只对前 200 条执行，避免分页深处开销失控。

### 2）首页推荐层

- `recommender.py` 的 `rank_opportunities` 合并：
  - 简历关键词、用户偏好（研究方向、专业、目标类型、地区）
  - 收藏行为（权重更高）
  - 点击行为（90 天内、去重）
  - 最近搜索行为（时间衰减）
  - 来源可靠度和质量、时效
- 输出包含：
  - `recommendation_components`（评分组件）
  - `recommendation_reasons`（可解释项）
  - `recommendation_version`（版本标识）

### 3）简历匹配（检索排序联动）

- `resumes.rank_by_resume` 在 `sort=resume` 时进行二次筛选与排序：
  - 仅保留有 `resume_match` 证据的岗位
  - 与 `recommender` 混合行为后仍保留可解释证据。

## 保护机制（防噪音）

- 行为权重做时间衰减；重复搜索词去重。
- `source_type` 与 `source_url` 做源分散：前段列表避免同机构同来源过度聚合。
- 搜索结果与推荐列表都不直接写入跨用户共享模型，减少隐私/偏置风险。

## 已知边界与下一步

- 目前无协同过滤训练、无个性化模型离线训练。
- `recommender_version` 未来可用于 A/B 对比，但需补齐评测框架（CTR/留存/命中率）。
- 大规模场景下可将 TF-IDF/主题向量与行为特征统一到持久化索引中，替换临时缓存。


## 当前实现补充（2026-09-10）

- 推荐理由继续保留 `recommendation_reasons` 与 `recommendation_components`，并加上收藏进度字段在收藏页单独管理。
- 继续保持行为不跨用户、不回写全局模型。
- 下一步如需协同过滤，先补齐 CTR 与留存的日志化指标，再做 offline A/B。
