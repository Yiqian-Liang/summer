# 简历上传与个人化匹配

平台提供“本地解析 + 本地化管理 + 匹配证据可解释化”，用于在搜索与推荐中加入个人匹配度。

## 入口

- `/resume` 页面
- `/resume/review` 本地规则检查页；可传 `opportunity_id` 针对一项机会检查

## 文件解析与保存

### 解析入口

- `POST /api/resume/parse?filename=<文件名>`（流式上传）
- 内容限制：
  - 文件最大 `2 MiB`
  - 格式：`.pdf` / `.docx` / `.txt`
  - DOCX/ZIP/XML 异常会拒绝
  - PDF 仅支持未加密、每页可解析并且最多 20 页

解析结果会回传 `text` 与系统自动抽取的 `keywords`（非持久化）；超时将失败。

### 保存入口

- `GET /api/resume`：读取当前已保存简历。
- `PUT /api/resume`：保存/更新（带并发保护）。
- `DELETE /api/resume`：删除。

保存约束：

- `filename`: 1–180，默认“粘贴的简历”。
- `text`: 最少 20 字，最多 30000 字。
- `keywords`: 1–20 个，每项 1–60 字，不接受联系方式或路径符号，需在正文证据中可被找到。
- `enabled`: 控制是否参与匹配；关闭后仅保留文字。
- `updated_at` 并发冲突返回 `409`。

## 匹配机制

匹配采用关键词证据链（不是硬规则打分）：

- 系统会对简历关键词与岗位文本（标题/描述/要求）逐一做逐词证据比对。
- 命中时返回 `resume_match`：
  - `count`：命中关键词数
  - `matched_keywords`
  - `evidence`：岗位与简历各自命中的证据片段

## 搜索与推荐中的行为

- API 搜索：`GET /api/search?sort=resume&q=...`
  - 需要登录且有已启用简历。
  - 有 `q` 时先保留原有检索过滤，再按匹配重排。
- 邮箱工作台/详情页的“我的简历依据”会展示部分命中证据。
- 首页推荐也会融合匹配信息与行为反馈。

## 免费本地检查

- `GET /api/resume/review` 返回当前登录用户的确定性检查结果；没有已保存简历时返回 `404`。
- 检查教育、研究/项目、技能等基础栏目是否有清晰标题。
- 检查日期格式是否混用、月份是否有效、日期区间是否倒置，以及经历是否缺少日期。
- 对研究/项目要点逐条展示行动词、方法/工具和可验证结果的文字依据；未检出时只标记“请核对”。
- 检查重复出现的空泛表达，并生成不带分数的修改清单。
- 传 `opportunity_id` 时返回现有 `matched_evidence`，以及项目提到但简历正文未检出的已知方向/技能 `missing_terms_for_review`。后者不等同于用户不会，也不应据此自动淘汰机会。
- 目标机会可以是公开机会，也可以是属于当前登录用户的私有外部导入；其他用户的私有记录返回 `404`。

检查使用固定本地规则，不联网、不调用 LLM、不生成录取概率或数字评分。它检查的是当前文本表达，不能验证经历真实性，也不会替用户补写未经确认的成绩。

## 隐私与安全边界

- 解析与匹配文本保存在 `user_resumes` 表中，仅用户可见。
- 数据库内文字未再加密；请按环境策略设置数据库权限。
- 上传/保存操作与行为记录都需要登录与 CSRF 校验。
- 检查页面和接口需要本人登录并使用 `no-store` 响应；接口只返回当前账号的简历元数据和检查证据。
