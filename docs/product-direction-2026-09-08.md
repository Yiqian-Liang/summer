# 为什么用户会来暑研通

当前设计假设：用户有明确的暑研/科研申请需求时，愿意用一个专门工作台减少重复搜索、比较和准备材料的时间。这需要通过真实使用验证，并非已有的市场结论。

## 这次落地的设计（已实现）

首页把价值改成“把分散的研究机会整理成你的申请清单”，入口明确展示跨来源筛选、原文可追溯、收藏、邮件与申请附件。减少“平台即广告”的叙事，避免固定“10+ 平台”与炫技式 AI 宣传。

搜索页强调先比研究方向和来源证据，再看申请要求；截止时间不明时回到原文确认。检索支持内容匹配、合并重复、过滤明显过期结果，来源入口统一保留。

邮箱、附件和收藏已串在同一个申请流程：

- 收藏机会后可在 `/saved` 做跟进阶段和截止提醒。
- 邮件工作台支持无连接下先起草/保存，连接邮箱后再确认并逐封发送。
- 附件支持本地上传与版本控制，不影响模板与 AI 草稿。
- 草稿与资料仍用用户本地会话隔离。

## 价值闭环（用户为什么会持续回来）

| 用户正在做什么 | 暑研通应该帮他省下什么 | 如何验证 |
| --- | --- | --- |
| 找某方向、某地区的机会 | 重复在多个平台和群内抓线索、阅读无关内容 | 相同任务下，比较找到合格机会的时间与有效结果数 |
| 判断是否值得申请 | 整理截止日、申请要求、资金与原文依据 | 能否在 5 分钟内说清“适合我在哪里、还缺什么信息” |
| 联系并准备材料 | 在收藏、简历、邮箱之间反复搬运材料 | 从收藏到可发送草稿的步骤是否可控、有无遗漏附件 |
| 导师招人 / 学生交流 | 找到同类目标与经验 | 招募发帖和经验帖的有效响应率（有回复） |

## 本轮已落实项（2026-09-10）

- 智能搜索主链路：本地检索 + 首屏在线补充 + 去重 + 语义重排（上限保护）+ 分页。
- 社区生态：科研招募/经验分享/讨论发帖、审核字段校验、公开展示和评论。
- 邮件工作台：模板起草 + 可选 AI 起草 + 多邮箱绑定（SMTP/OAuth）+ 附件 + 发送确认 + 发送状态保护。
- 简历匹配：解析确认、关键词抽取、基于证据的简历匹配排序与匹配依据可视化。
- 收藏进度：保存阶段（准备中/已联系/已申请/已回复）、提醒天数、备注，自动结合截止日显示提醒状态。

## 下一步优先级（不在本轮扩展）

1. 对“邀请新用户首屏”继续做体验验证：先演示“可行得出的价值路径”，再追加复杂引导。
2. 增加可度量指标：
   - 收藏后到邮件起草/发送的转化率
   - 招募帖到外部申请动作的转化率
   - 留存到下一轮跟进的比例
3. 引入更轻量的“机会对比视图”而非复杂编辑器。
4. 在明确用户支付意愿后引入 AI 配额/计费模型。
