# 暑研通产品方向与实施状态

首批用户是申请全球计算、AI 及交叉方向暑研、RA、PhD 机会的中国学生。产品目标不是复制微信、小红书、LinkedIn 或 X 的综合信息流，而是接住这些渠道中的线索，让用户在一个地方完成核验、比较、准备、联系、跟进和复盘。

平台长期保存的核心资产是用户自己的申请清单、截止日期、材料与邮件版本、联系记录、回复和结果。北极星指标是“每周完成至少一个真实申请动作的用户数”；搜索量、浏览时长和帖子数只作辅助观察。

## P0：申请行动工作台（已实现）

### 申请清单与跟进

- 主入口为 `/applications`，`/saved` 保留兼容。申请按今天要处理、准备中、已联系、已申请、有回复、已结束分组。
- 每项可记录 `preparing → contacted → applied → replied → interviewing → completed` 阶段、`email/form/other` 申请方式、下一步时间、备注及 `accepted/rejected/withdrawn/no_response` 结果。
- 阶段与结果写入累计时间点；已有旧收藏迁移后保持准备中、邮件申请和原提醒默认值。
- 卡片可打开原文、查看简历匹配依据、进入本地简历检查、起草邮件、选择附件，并回看该项目的草稿/发送状态与附件数量。
- 邮件只有在邮箱服务明确返回成功后才把申请标为已联系并生成七天后的跟进；失败或结果未知不改变申请阶段，也不自动重发。

### 外部线索与比较

- 用户可粘贴 URL、标题和可选摘要建立私有申请卡。平台只规范化和保存输入，不抓取登录态页面。
- 同一账号按规范化 URL 去重；不同用户彼此隔离。私有导入只保存在用户申请表，不进入公共机会表、搜索或推荐。
- 私有导入缺少的截止日期、资金和要求显示为待核验，导入后即可记录进度、写邮件或参与比较。
- `/applications/compare` 接受本人 2–4 条不同申请，并排展示研究方向证据、机构/导师、截止日期、申请方式、原文要求、联系方式、待核验项和下一步。越权、重复及数量不符会拒绝。
- 比较结果不输出录取概率或伪精确综合分。

### 免费简历检查

- `/resume/review` 与 `GET /api/resume/review` 基于已确认的当前简历工作，可选 `opportunity_id`。
- 本地规则检查教育、研究/项目、技能栏目，日期格式和倒置区间，经历要点中的行动、方法、可验证结果，以及重复空泛表达。
- 针对项目时展示简历和项目原文的共同证据；项目提到但简历未检出的已知方向/技能统一标为“请核对”，不推断用户不会。
- 检查不联网、不调用 LLM、不输出数字评分；公开机会和属于当前用户的私有导入都能使用。

### 待办、日历与数据闭环

- 首页和申请页显示“今天该做什么”，来源包括已到期的下一步、进入提醒窗口的截止日期、准备中的申请缺少当前简历，以及私有线索待核验。
- `GET /api/applications/calendar.ics` 可导出全部或单个本人申请的明确截止日期；无可解析日期的记录会跳过，文本按 iCalendar 规则转义。
- 提醒目前只有站内待办和用户主动下载的 `.ics`。平台不会读取邮箱或通过已绑定邮箱自动发送提醒。
- 现有 SQLite 时间点足以计算发现/收藏或导入、起草、联系或提交、回复和结果的漏斗；当前没有额外建设分析平台或学习排序模型。

### 邮件、附件与上线保护

- 邮件工作台支持免费模板、私有草稿、最多五个邮箱、SMTP/Google/Microsoft OAuth，以及逐封人工确认发送。
- 附件已经实现上传、列表、下载、移除、发送确认和实际 SMTP/OAuth 发送。每封最多 5 个、合计 2 MiB，每用户附件存储 20 MiB；附件不交给 AI。
- `POST /api/collect` 是维护接口，要求请求头 `X-Admin-Token` 与 `ADMIN_API_TOKEN` 一致；未配置时不可用。
- `/api/analyze-match` 要求登录并受持久限流保护。默认返回本地证据；只有 `ENABLE_MATCH_AI=1`、有效 `GEMINI_API_KEY` 和用户主动请求同时满足时才补充 AI 分析。
- 注册、发帖、评论、AI 请求和在线搜索使用 SQLite 持久化固定时间窗限流，强制刷新另有更低配额；匿名主体使用经 `RATE_LIMIT_SALT` 加盐的地址哈希。当前单机实现不宣称支持多主机全局配额。

## P1：导师供给与可信社区（门槛未达，保持后续）

当前社区已经支持科研招募、经验分享、讨论和评论；只有已发布招募进入机会检索，作者身份明确为未核验。导师认领、候选管理和验证体系尚未实现。

只有同时达到至少 30 名试用学生、100 张真实申请卡，且多数测试者完成第二次申请动作后，才进入 P1：

- 机构邮箱验证与官方实验室页面认领。
- 实验室最新确认时间及仍在招/已招满状态。
- 带方向、方法、资格、时间、资金、名额、材料和渠道的结构化招募。
- 学生标准意向卡和导师轻量候选列表。
- 经验帖结构化申请字段，讨论帖采纳回答/已解决状态，以及举报、管理员下架和发布者验证。

在门槛前不建设关注、粉丝、通用私信或完整 ATS。

## P2：科研合作、资源与选题（P1 验证后再做）

P2 仍是待验证方向，当前没有上线合作撮合、仪器交易或论文选题 AI：

- 先在计算与 AI 圈验证找合作者、方法支持、数据集、算力、标注和复现伙伴的结构化需求板与能力目录。
- 合作需求记录贡献方式、时间、预算、署名/IP 预期和状态，通过意向卡联系，不扩建通用聊天。
- 选题工作台只组织问题、对象、方法、数据、基线、资源、周期和伦理约束，并关联论文与合作需求；不自动宣称“发现研究空白”。
- 仪器方向先验证能力目录、需求发布和官方预约链接。实时排期、计费、培训资格、合同与支付需等到有学校合作方后再做。

## 商业与算法默认

搜索、申请管理、本地简历检查和模板邮件保持免费。AI 邮件和项目分析均为管理员启用后由用户主动选择的补充能力；当前不建设订阅、付费墙或用户 API Key 管理。

推荐继续使用可解释的内容、简历、偏好和本人行为。至少积累数百条已完成申请结果并通过时间切分离线评估后，才考虑学习排序；学校名气、姓名、年龄等敏感特征不进入匹配。
